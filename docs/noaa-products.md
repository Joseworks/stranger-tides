# NOAA planning and additional station products

The explorer retains the immutable station inventory. Capability discovery enriches the public catalog at read time using NOAA's `waterlevelsandmet&expand=sensors` and `1minute` metadata collections, cached for six hours. No schema change or catalog rewrite is required. Failed discovery retains station search and marks capabilities unconfirmed.

Purple pins with a white dot highlight the currently selected product. The default Specialized sensors choice covers conductivity, salinity/specific gravity, visibility and bridge-to-water clearance; common one-minute data alone does not qualify. Select a forecast, flood outlook, individual sensor, one-minute levels or Any additional product to change the highlight. Orange means another station, not a guarantee of missing data. The matching-only toggle and station layer stay synchronized; counts and the legend identify the selection, and shared links preserve `product` and `layer`.

Every station uses its own pin. Tap overlapping pins to spread them radially without zooming; dense overlaps have up to six stations per page (fewer on short screens), plus search across the entire overlap set. Expanded choices preserve selected-product colors and station IDs. Selecting one leaves the map center/zoom unchanged. Escape restores focus; movement, filters and resize dismiss the picker. New pins appear as the map pans, while existing unchanged pins are retained. Advertised capability does not guarantee a recent reading.

## Planning and history

`GET /stations/:id/report` accepts `hours=24|48|72|168|720`, `future_hours=0|24|72|168|720` and `units=english|metric`. The UI defaults to 48 hours of history and seven days of future tides. Past and future requests are separate so the combined window never exceeds NOAA's per-request month limit. Future predictions have a separate chart and a high/low calendar. Subordinate prediction stations remain discrete high/low events; no continuous curve or interpolated departure is invented.

Observed-minus-predicted values are calculated only for exact matching timestamps in the same requested datum and units. Missing values and flagged observations remain gaps. This is a difference from the astronomical prediction, not attribution of the difference to a particular cause. Great Lakes stations retain their IGLD elevation explanation and do not acquire fictitious astronomical tides.

History, planning, units and timezone controls update graphs in place, preserve scroll position and update shared URL parameters. Measurement tables load on demand with bounded initial rows and a show-more control. New charts also have on-demand measurement tables. All displayed timestamps follow browser/station/UTC selection; NOAA daily flood-outlook dates remain calendar dates.

## Optional products

`GET /stations/:id/context?units=english|metric` independently requests advertised OFS guidance within the next 48 hours, one-minute preliminary observations for the past 24 hours, a seven-day high-tide flooding outlook where available, and links to other published NOAA station products. Each optional request can fail without replacing the main report. Structured `failed_products` and `failed_buoys` identify partial transport failures even when the endpoint returns HTTP 200. Automatic updates merge successful data and retain only failed products/instruments in compatible units/datums, with previous-data feedback and instrument timestamps; successful empty responses still clear prior plots. A retry control reloads additional products without re-fetching the core report.

OFS uses the same datum as the observed chart, including IGLD where NOAA supports it. The high-tide flooding endpoint explicitly requests MLLW and the selected units; its NOS minor threshold is labelled with that reference and the model's update date. Raw MDAPI flood thresholds do not declare their reference, so they are not blindly plotted on an MLLW/IGLD chart. Outlook likelihoods are not weather watches or warnings. An empty outlook is unavailable data, not a zero flood likelihood.

The sensor adapter supports every documented scalar CO-OPS station observation product represented here: wind/gust/direction, air/water temperature, pressure, humidity, conductivity, derived salinity/specific gravity, visibility and air gap. Disabled instruments are not queried; an enabled duplicate sensor takes precedence. Unsupported instrument names (for example an unspecified analog channel) are not mapped to invented API products. Other NOAA web products remain accessible through validated HTTPS NOAA links.

`GET /stations/:id/nearby?hours=...&units=...` uses NDBC's active XML catalog and standard meteorological text feeds. It examines at most three reporting buoys within 200 km, ordered by great-circle distance. Fixed shore instruments are excluded. Names, coordinates, source links, distance, latest measurement and stale status identify each buoy as a separate location. Wave height/period/direction, wind/gust/direction, temperatures and pressure are graphed when present. Buoy charts load when expanded. Missing columns and `MM` values remain absent/gaps; SI heights, speeds and temperatures are converted explicitly for US displays. A nearby buoy is not claimed to represent the selected harbor's conditions.

Station IDs and request options are validated before outbound access. CO-OPS and NDBC clients use fixed official origins and fixed path templates, bounded timeouts and cached responses. NDBC paths accept only five-character station IDs, XML parsing disables network access, and responses have a size limit. Incoming NOAA product URLs are never fetched by the server; only approved NOAA HTTPS links are shown. No credentials or user coordinates are sent by these new services.

## Validation

RSpec checks exact-time differences, zero/null/quality handling, bounded planning windows, IGLD, conditional capabilities, malformed/upstream failures, safe product links, buoy selection/parsing/conversion and input validation. Browser regressions cover individual pins, radial overlap selection/search/paging/focus and product filtering, future and longer history, no reload/scroll, optional failures/retry, extra sensor units, buoy graphs and timezone propagation. Fixtures never call NOAA or use production databases. Hosted checks separately verify real services and maps.

Live read-only verification on November 14, 2026 found 324 of 3,644 saved locations advertising at least one additional supported product: 253 one-minute, 160 model forecasts, 109 flooding outlooks, 26 conductivity/salinity/specific gravity, 21 visibility and 21 air gap. These are discovery counts, not guaranteed current readings; counts change as NOAA updates metadata. Hilo returned future tides, differences and flooding outlooks; Duluth returned IGLD model guidance; Sewells Point returned conductivity/salinity; buoy 51206 returned Hilo-area waves.

## Fixed historical dates and CSV

Expand **Explore historical dates & export CSV** in a station report. The separate historical view accepts inclusive start/end dates in UTC, units from the main controls, and Automatic / six-minute / verified hourly / verified monthly resolution. It never replaces current conditions with an old reading or labels an old archive as stale live data. Live report refreshes do not repeatedly fetch the archive. Shared links preserve `begin_date`, `end_date` and `resolution`; displayed hourly/six-minute timestamps follow the selected timezone, while monthly periods remain calendar months.

`GET /stations/:id/history` validates catalog membership, ISO dates from 1800 through today, units and resolution before calling NOAA. Automatic chooses six-minute `water_level` through 30 inclusive days, verified `hourly_height` through 365, then `monthly_mean` through 2,400 calendar months. Requests are bounded, cached for one hour and share a 20-second deadline; no unbounded chunking occurs. Verified data may be unavailable for recent months. Monthly requests cover full calendar months and plot NOAA's `MSL` field relative to the selected water-level datum (including IGLD), preserving inferred flags and null gaps. They do not plot a fictitious instantaneous height or calculate tides/departures from a monthly average. Hourly and six-minute predictions use matching intervals; subordinate stations remain high/low points. Differences compare exact, unflagged timestamps only.

CSV exports all loaded historical observations, predictions and differences, including rows beyond the on-screen table limit, without another NOAA request. Columns identify station/name/state, product, resolution, datum, units, requested UTC dates, UTC timestamp or calendar month, value, quality, flags/event and retrieval time. Missing values stay empty, real zero and negative heights are preserved. Every cell is quoted; formula-like untrusted text is neutralized. Downloads use a local browser Blob and do not upload data elsewhere. Date/resolution changes and failed loads disable export so an old result cannot be downloaded under a new range. Current weather, forecast and buoy sections remain current products, not historical weather archives.

See [NOAA request limits and verified products](https://api.tidesandcurrents.noaa.gov/api/prod/) and [monthly response fields](https://api.tidesandcurrents.noaa.gov/api/prod/responseHelp.html). Physical download/permission/fullscreen behavior is recorded separately in the [device acceptance checklist](device-acceptance.md).

## Map-first staging interface

The explorer starts with the map and one search field. Filters and the station list are independent, dismissible drawers; typing opens matching results. Selecting a station opens a compact Now panel below the map on phones and beside it on larger screens. Now, Tides, Weather and History are accessible keyboard-operable tabs; selected tabs are shareable with `tab=now|tides|weather|history`. Historical date links open History directly, even when current data fail.

Tides holds the recent water-level chart, with future predictions/differences and forecast/flood context in disclosures. Weather holds station sensors and nearby buoys; History retains fixed dates and CSV. Units, timezone and live-update preferences remain in Display & live updates. Datum, units, quality and stale/failure feedback stay visible with the current reading; raw sensor status and metadata are in Station details. Each tab remembers its panel scroll, and charts reflow when revealed without changing saved ranges/series state. Small centered orange/purple circle markers preserve selected-product highlighting; the selected marker is larger. Overlapping stations still spread radially without forced zoom. No account, location permission, catalog or NOAA-service changes are introduced by this layout.

Station photos use NOAA's public [photo index](https://cdn.tidesandcurrents.noaa.gov/assets/stationphotos/photo.json), the same source used by its station home pages. The application caches this index for one day and constructs only fixed NOAA CDN image URLs from validated station IDs and index suffixes. `GET /stations/:id/photo` validates the station against the saved catalog, independently of live observations. The Now tab's Station photo disclosure loads one archive image on demand, credits NOAA CO-OPS and links to the official gallery. Missing images, unavailable feeds and late responses after station changes do not affect station readings. These are photographs, not live webcams.
